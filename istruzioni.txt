✅ SÌ, useremo interrogazioni API (REST) dal software aziendale.
E ti spiego perché è la soluzione migliore e più semplice, senza alternative inutili.

🟦 1) Lato software aziendale → ci colleghiamo via HTTP alle API
Il tuo software interno (Windows, Python, C#, VB, quello che vuoi) farà:
GET https://tuo-backend/api/pasti/{utente}

e riceverà:
JSON[  {    "id": 12,    "utente": "Francesco Dell'Oste",    "ristorante": "Orto dei longobardi",    "data": "2026-02-17",    "importo": 7.50  },  ...]``Mostra più linee
Fine.
Niente complicazioni.
È la lettura che chiedi tu.

🟦 2) NON serve nessun REST “avanzato”
Tu hai bisogno solo di:


1 endpoint per ogni utente:
GET /api/pasti/{utente}


1 endpoint totale:
GET /api/pasti/{utente}/totale


Basta.
Non serve POST, PUT, DELETE lato azienda.
(Quelli servono solo alla PWA.)

🟦 3) Perché non leggere direttamente SQLite o MySQL del backend?
Ti spiego subito, così eliminiamo tutti i dubbi:
❌  Non si legge SQLite del backend
Perché è locale nel server (o Render) e non è pensato per accesso remoto.
❌  Non si legge MySQL “cloud” direttamente dalla tua azienda
Per motivi di sicurezza e firewall.
✔️  L’unico modo sano e approvabile da IT
è interrogare API HTTPS.
È lo standard ovunque.
